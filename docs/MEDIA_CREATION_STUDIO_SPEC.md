# مواصفات استوديو الصور والفيديو والصوت في NIKO

**الحالة:** مواصفات تجربة ومخرجات ومعايير قبول؛ لا تعني وجود محركات إنتاجية مهيأة.
**الهدف:** توفير مساحة إبداعية موحدة داخل NIKO لإنشاء الصور والفيديو والصوت وتعديلها ومراجعة نسخها وتصديرها.

## 1. المبادئ

- المستخدم يصف النتيجة بلغته الطبيعية، وNIKO يختار المسار والمحرك المناسبين.
- يدعم وضع Agent لتخطيط المشاهد واختيار المحركات تلقائياً، ووضع Manual للمستخدم المتقدم.
- يظل لكل مشروع سجل prompts ونسخ وأصول ومخرجات معزولة حسب المستخدم.
- لا تُعرض معاينة أو صورة placeholder على أنها ملف ناتج.
- لا يبدأ توليد مدفوع قبل عرض التكلفة/السقف والحصول على موافقة مناسبة.

## 2. استوديو الصور

### إنشاء الصور
- وصف نصي إلى صورة.
- أبعاد ونسب شائعة: 1:1، 4:5، 3:4، 9:16، 16:9، وأبعاد مخصصة ضمن حدود المحرك.
- اختيار الجودة والحجم وعدد النتائج عندما يدعم المزود ذلك.
- دعم وصف عربي وإنجليزي وتركي، مع إمكانية تحسين prompt داخلياً دون تغيير المعنى.
- دعم مرجع بصري مع موافقة المستخدم وحقوق استخدام الصورة.

### تعديل الصور
- تعديل موضعي باستخدام mask/brush عند توفره.
- إزالة/تغيير الخلفية، استبدال عنصر، توسيع الصورة، تحسين الإضاءة/الألوان، تغيير النمط، تنظيف عيوب.
- حفظ الصورة الأصلية دون تعديل، وكل نتيجة كنسخة جديدة.
- إظهار مقارنة قبل/بعد وتاريخ التعديلات.
- لا تُقبل الصورة كمدخل اعتماداً على امتداد الملف فقط؛ افحص MIME والتوقيع والحجم.

### إدارة النتائج
- معاينة بدقة مناسبة، عرض الأبعاد والصيغة والحجم والمحرك المستخدم.
- تنزيل الملف الأصلي، مشاركة بعد موافقة، حفظ في مكتبة المستخدم.
- إعادة التوليد من نفس prompt أو نسخة معدلة.
- حذف الأصل والنسخ المرتبطة وفق سياسة الحذف.

## 3. استوديو الفيديو

### أنماط التوليد
- نص إلى فيديو.
- صورة إلى فيديو.
- فيديو مرجعي إلى فيديو/تحرير عند دعم المحرك.
- بداية/نهاية المشهد، صور مرجعية متعددة، وصف حركة الكاميرا.
- مشاهد متعددة مع storyboard وتسلسل لقطات.
- تحويل فكرة أو نص إلى shot list، ثم توليد كل لقطة، ثم تجميعها.

### إعدادات الفيديو
- مدة المقطع وفق حدود المزود الفعلية.
- نسب 9:16 و16:9 و1:1.
- الدقة ومعدل الإطارات إن كانا مدعومين.
- عدد المشاهد والمخرجات.
- الصوت الأصلي أو تعليق صوتي أو موسيقى أو مؤثرات مع مراعاة الحقوق.
- إظهار قيود النموذج قبل بدء المهمة، لا بعد استهلاك الرصيد.

### التحرير والتجميع
- قص ودمج وترتيب المقاطع.
- انتقالات بسيطة، نصوص وعناوين، ترجمة/تعليقات، شعار المستخدم.
- مزامنة الصوت والتعليق، ومستوى الصوت.
- إخراج MP4 صالح مع codec/container موثقين.
- حفظ المشروع القابل للتحرير ومصادره حيثما تسمح البنية.
- لا تدّعِ تحريراً غير تدميري إذا كان الناتج ملفاً مسطحاً فقط.

### المهام الطويلة
- إنشاء job غير متزامن.
- حالات queued/running/awaiting_approval/succeeded/failed/cancelled/expired.
- polling أو webhook موثق، timeout، إلغاء، واسترجاع الحالة بعد إغلاق التطبيق.
- لا تعِد إرسال الطلب عند timeout قبل التحقق من حالة المهمة أو idempotency.
- التحقق من أن ملف MP4 موجود، غير فارغ، ويمكن قراءته قبل عرض النجاح.

## 4. الصوت والموسيقى

- تحويل نص إلى تعليق صوتي بلغات NIKO الأساسية.
- صوت رجالي كاختيار افتراضي مفضل عندما يتوفر صوت مناسب.
- التحكم في السرعة والنبرة والوقفات دون تقليد صوت شخص حقيقي دون موافقة وحقوق واضحة.
- مزج التعليق مع الموسيقى والمؤثرات.
- لا تولد أو تستخدم موسيقى محمية بحقوق دون ترخيص.
- استنساخ الصوت يتطلب موافقة صريحة موثقة من صاحب الصوت، وإظهار أن الصوت مولد/مستنسخ عند الحاجة.
- لا تُعد ميزة توليد الموسيقى متاحة قبل وجود مزود قانوني ومهيأ واختبار ملف فعلي.

## 5. تجربة المشروع

لكل مشروع:
- اسم، وصف، نوع المشروع، لغة المحتوى، أبعاد/منصة الهدف.
- assets أصلية ومراجع ونتائج.
- prompt وإصداراته وإعدادات المحرك.
- storyboard/shot list عند الفيديو.
- قائمة jobs وحالتها.
- نسخ نهائية وتصدير.
- سجل موافقات وتكاليف مختصر.
- إمكانية إعادة فتح المشروع من جهاز آخر بعد تسجيل الدخول.

يجب أن تكون الواجهة مناسبة لشاشة iPhone: محرر خطوة بخطوة، معاينة واضحة، تحكم بالإيقاف، عدم حشر إعدادات متقدمة في المسار الأساسي، مع إتاحة التفاصيل المتقدمة عند الطلب.

## 6. حقوق المحتوى وسلامته

- يتحمل المستخدم مسؤولية امتلاك حق استخدام الصور/الفيديو/الصوت الذي يرفعه، مع عرض السياسة بوضوح.
- تطبيق قيود المزود والقانون وحقوق النشر والعلامات التجارية.
- عدم إزالة العلامات المائية أو تجاوز القيود التعاقدية.
- لا تحفظ الصور أو الفيديو الخاص في روابط عامة دائمة.
- لا تنشر أو تشارك أو ترسل أي مخرج خارج الحساب دون موافقة صريحة.
- لا تُستخدم مخرجات المستخدم للتدريب دون opt-in منفصل.

## 7. البنية الفنية

- Media Project Service لحفظ المشاريع والنسخ.
- Provider Router لاختيار image/video/audio adapters.
- Durable Job Queue للمهام غير المتزامنة.
- Private Object Storage مع فحص الملفات وsigned URLs قصيرة العمر.
- Media Validation Worker لفحص الصيغ والمدة والحجم والترميز.
- Quota/Spend Manager قبل الإرسال إلى المزود.
- Approval Manager للنشر/المشاركة/العمليات المدفوعة.
- Audit metadata منقح.
- فصل مسارات الفيديو عن API التفاعلي حتى لا تحتجز request threads.

## 8. معايير القبول

### الصور
- توليد صورة حقيقية من prompt بمزود مهيأ.
- تحرير صورة فعلية مرفوعة مع الاحتفاظ بالأصل.
- التحقق من ملف الصورة وأبعاده وحجمه.
- اختبار فشل المزود والمهلة وحدود الاستخدام.

### الفيديو
- بدء مهمة حقيقية ومتابعة الحالة حتى النهاية.
- استرجاع الحالة بعد إعادة فتح التطبيق.
- إلغاء مهمة إن كان المزود يدعم ذلك.
- تنزيل MP4 والتحقق من صلاحية الملف ومدة الفيديو.
- اختبار فشل جزئي وتجميع المشاهد.

### الصوت
- توليد ملف صوتي حقيقي للغات المعلنة.
- مراجعة نطق الأسماء والمصطلحات واللهجات.
- التحقق من الترخيص وعدم انتحال صوت دون إذن.

### الأمان والتكلفة
- مستخدم B لا يستطيع قراءة/تنزيل/تعديل مشروع أو أصل مستخدم A.
- روابط التنزيل تنتهي صلاحيتها.
- حدود المستخدم والتكلفة تمنع تجاوز السقف.
- لا يتم تشغيل أي مزود مدفوع في CI.

## 9. تعريف الإنجاز

لا تُعلن أي فئة وسائط جاهزة إلا بعد اختبار end-to-end بمزود مهيأ، وملف مخرج حقيقي صالح، وتجربة iPhone، واختبارات العزل والخصوصية والتكلفة. وجود واجهة أو mock أو endpoint لا يكفي.
