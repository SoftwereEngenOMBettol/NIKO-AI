# استراتيجية منصات NIKO

## القرار
- **المنتج الأول: iPhone / iOS.**
- **المنتج التالي: Android** بعد استقرار تجربة iOS الأساسية.
- **إطار التطبيق: Flutter** بقاعدة كود مشتركة قدر الإمكان.

هذا القرار يحدد ترتيب التصميم والتنفيذ والاختبار، ولا يعني إسقاط Android أو كتابة تطبيقين منفصلين.

## ما يعنيه iPhone أولاً
1. كل ميزة تُراجع أولاً وفق إمكانات iOS وقيوده.
2. قبول الواجهة يتطلب اختبار Safe Areas ولوحة المفاتيح والتنقل وإمكانية الوصول على iPhone.
3. الصوت والميكروفون والإشعارات ودورة حياة التطبيق تُصمم وفق سياسات iOS.
4. لا نعد بالاستماع الدائم لكلمة «نيكو» أو تنفيذ مهام مستمرة في الخلفية على iPhone.
5. تخزين البيانات والأسرار والصلاحيات يخضع لمراجعة خصوصية iOS.
6. لا تعتبر ميزة مكتملة لمجرد نجاحها على Android Emulator.

## مشاركة الكود
- منطق المحادثة، إدارة اللغة، التخطيط، المهارات، النماذج، والتحقق من الموافقات يبقى في طبقات Dart مشتركة.
- تفاصيل النظام تمر عبر Platform Adapters.
- يُنفذ iOS Adapter ويُختبر أولاً.
- يُضاف Android Adapter عند الحاجة لاحقاً، دون تسريب اعتماديات النظام إلى NIKO Core.

## بيئة التطوير والبناء
- Windows مناسب لتطوير Flutter وDart وتشغيل التحليل والاختبارات.
- لا يدعم Windows تشغيل Xcode أو iOS Simulator أو بناء iOS محلياً.
- macOS وXcode مطلوبان لبناء iOS وتشغيل المحاكي وتوقيع التطبيق.
- GitHub Actions على macOS يستطيع بناء تطبيق iOS Simulator دون توقيع للتحقق الآلي.
- ملف Simulator الناتج ليس IPA ولا يثبت على iPhone حقيقي.
- اختبار iPhone فعلي وتوزيع التطبيق يتطلبان إعداد توقيع Apple المناسب. لا تُشترى خدمة أو عضوية أو يُفعّل اشتراك قبل عرض التكلفة والموافقة.

## ترتيب التنفيذ
1. استمرار تطوير Flutter على Windows.
2. نجاح اختبارات Dart/Flutter.
3. نجاح بناء iOS Simulator على GitHub Actions macOS.
4. تجهيز macOS/Xcode والتوقيع عند الانتقال إلى اختبار iPhone حقيقي.
5. اختبار المحادثة والصوت والأذونات والخصوصية والأداء على iPhone.
6. استقرار MVP على iPhone.
7. استكمال Android build والاختبارات والوظائف الخاصة به.
8. بعد ذلك، توسيع التكاملات الخارجية والمهارات وفق الأولوية والتكلفة.

## بوابات القبول
| البوابة | دليل النجاح |
|---|---|
| Flutter مشترك | التحليل والاختبارات تمر |
| iOS CI | نجاح بناء Simulator على macOS |
| iPhone حقيقي | نسخة موقعة تثبت وتعمل على جهاز فعلي |
| MVP iOS | اجتياز اختبارات المحادثة والصوت والخصوصية والمهام المعتمدة |
| Android لاحقاً | بناء واختبار القاعدة المشتركة مع adapters المناسبة |

## قيود لا نتجاوزها
- لا نستخدم حلولاً تلتف على قيود iOS الخلفية أو صلاحياته.
- لا نضع مفاتيح API أو أسرار توقيع في GitHub.
- لا نعتبر بناء المحاكي بديلاً عن اختبار الجهاز الحقيقي.
- لا نغيّر إطار التطبيق لمجرد أن مسار Android أسهل؛ يُراجع القرار فقط إذا ظهرت مشكلة مثبتة تمنع تحقيق متطلبات iPhone.
