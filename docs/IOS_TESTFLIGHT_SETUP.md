# تجربة NIKO على iPhone دون اشتراك Apple Developer

## القرار

لا نستخدم TestFlight أو توقيع IPA أو Apple Developer Program في مسار التجربة المجاني. حساب Apple العادي لا يتيح TestFlight أو توزيع IPA على أجهزة الآخرين.

المسار المعتمد للتجربة الأولى هو بناء نسخة Flutter Web قابلة للتثبيت على الشاشة الرئيسية (PWA) وفتحها من Safari على iPhone. هذا لا يتطلب Mac أو Xcode أو رسوم Apple.

## ما الذي يوفره هذا المسار؟

- فتح واجهة NIKO من رابط HTTPS في Safari.
- إضافة NIKO إلى الشاشة الرئيسية كاختصار/تطبيق ويب.
- تجربة الواجهة وتدفق الإدخال النصي بعد نشرها على استضافة HTTPS.
- دعم إدخال الصوت والإخراج الصوتي بقدر ما يسمح به Safari وإضافات Flutter على الويب، بعد اختباره على الجهاز.

## ما الذي لا يوفره؟

- ليس تطبيق iOS أصلياً ولا ملف IPA.
- لا يوفر TestFlight أو App Store.
- لا يضمن تشغيل الميكروفون أو الاستماع في الخلفية بعد مغادرة Safari أو قفل الهاتف.
- لا ينفذ كلمة التنبيه «نيكو» أثناء عمل تطبيقات أخرى.
- لا يجعل المحادثة تعمل قبل إكمال المصادقة؛ API المحادثة يتطلب JWT، وعميل Flutter الحالي لا يرسل رمزاً ولا يحتوي على تسجيل دخول.
- Backend الحالي متوقع أن يعمل مع Ollama على جهاز مشغل للخادم. لا تضع عنوان localhost في نسخة الويب على iPhone؛ localhost على الهاتف يشير إلى الهاتف نفسه، وليس إلى كمبيوتر Windows.

## بناء معاينة الويب عبر GitHub Actions

1. افتح مستودع NIKO ثم **Actions**.
2. افتح workflow باسم **Build NIKO iOS and Web Preview**.
3. بعد تشغيله على فرع `feat/tab-ai-parity-foundation`، افتح أحدث تشغيل.
4. تحقق من نجاح مهمة `build-web-preview`.
5. نزّل artifact باسم `niko-ai-iphone-web-preview`. يحتوي ملفات الويب الثابتة، وليس IPA.

البناء يستخدم المسار الأساسي `/NIKO-AI/` ليتوافق مع GitHub Pages إذا قرر مالك المستودع تفعيل النشر لاحقاً.

## النشر على GitHub Pages (اختياري، يحتاج موافقة قبل جعل الرابط عاماً)

GitHub Pages قد يجعل واجهة المعاينة متاحة لأي شخص يملك الرابط، لذلك لا يتم النشر تلقائياً في هذا المسار.

إذا وافق مالك المستودع على نشر واجهة عامة:
1. افتح **Settings → Pages** في GitHub.
2. اختر **GitHub Actions** كمصدر النشر.
3. أضف workflow نشر Pages منفصلاً بصلاحيات `pages: write` و`id-token: write`.
4. انشر ملفات `mobile/build/web` من تشغيل موثوق للفرع المقصود.
5. اختبر الرابط على iPhone عبر Safari قبل إضافته إلى الشاشة الرئيسية.

لا تضع أسراراً أو رموز دخول أو بيانات شخصية في ملفات الويب أو مستودع عام. لا تنشر الواجهة مع Backend غير محمي أو بيانات اختبار حقيقية.

## تثبيت واجهة الويب على iPhone

بعد توفير رابط HTTPS عام للنسخة المنشورة:
1. افتح الرابط في Safari على iPhone.
2. اضغط زر المشاركة.
3. اختر **Add to Home Screen / إضافة إلى الشاشة الرئيسية**.
4. فعّل **Open as Web App / الفتح كتطبيق ويب** إذا ظهر الخيار.
5. اضغط **Add / إضافة**.
6. افتح أيقونة NIKO من الشاشة الرئيسية.

قد تختلف أسماء الخيارات قليلاً حسب إصدار iOS واللغة.

## تشغيل المحادثة فعلياً

قبل اختبار المحادثة يجب إكمال عناصر الخادم:
- توفير Backend بعنوان HTTPS يمكن الوصول إليه من iPhone.
- توفير Ollama على خادم يمكنه الوصول إلى النموذج؛ لا تستخدم `127.0.0.1` من الهاتف.
- إضافة مزود هوية وتسجيل دخول حقيقي.
- تخزين JWT بأمان في العميل وإرساله في `Authorization: Bearer`.
- إعداد CORS للنطاق المنشور، مع عدم فتحه عشوائياً لكل النطاقات.
- عدم تضمين أسرار الخادم أو مفاتيح مزودي الخدمات داخل تطبيق الويب.

حتى اكتمال هذه العناصر، تكون معاينة الويب اختباراً للواجهة والبناء فقط، وليست تجربة مكتملة للمساعد الذكي.

## تجربة تطبيق iOS أصلي مجاناً لاحقاً

Apple تسمح بتثبيت تطبيق على جهازك الشخصي باستخدام Xcode وPersonal Team دون عضوية مدفوعة، لكن ذلك يتطلب Mac عليه Xcode، كما تنتهي ملفات التوقيع المجاني عادة بعد 7 أيام ويجب إعادة التوقيع والتثبيت. حساب Apple العادي وحده على Windows لا يستطيع توقيع IPA وتثبيته مباشرة.
