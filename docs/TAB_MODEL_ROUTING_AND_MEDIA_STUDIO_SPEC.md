# NIKO — مواصفات توجيه النماذج واستوديو الوسائط على معيار Tab

**الحالة:** مواصفات منتج ومعايير قبول. ليست دليلاً على أن موصلات المزودين أو التوليد الفعلي قد نُفذت.
**المرجع الوظيفي:** Tab (tab.bot / workspace.tab.bot)، وفق الصفحات العامة التي تمت مراجعتها في 15 نوفمبر 2026.
**قرار المنتج:** iPhone أولاً، NIKO مباشر دون Siri، مع Backend متعدد المستخدمين وموصلات قابلة للاستبدال.

## 1. ما الذي نعرفه عن Tab من مصادره العامة؟

Tab ليس نموذجاً واحداً؛ إنه مساحة عمل/وكيل إبداعي متعدد النماذج يختار نماذج مختلفة حسب المهمة، مع وضع تلقائي ووضع يدوي، وتدفق من الفكرة إلى الإنشاء ثم التعديل والتصدير.

الموديلات التي تعرضها صفحات Tab العامة وقت إعداد هذه المواصفات:
- **الفيديو:** Google Veo 3.1، Kling 3.0 Pro وKling 2.6 وKling o3 Edit/Ref، ByteDance Seedance 2.0 وSeedance 2.0 Fast، MiniMax Hailuo 2.3.
- **الصور:** Nano Banana Pro، Nano Banana 2، Seedream 5.0، GPT Image 2 (وتظهر بعض صفحات الإنشاء مسميات/إصدارات GPT Image أخرى؛ يجب التحقق من الاسم المتاح فعلياً في حساب المزود قبل الربط).
- **الصوت:** ElevenLabs 3.0 للتعليق/الصوت، Suno 5.5 للموسيقى، وMirelo 1.5 للمؤثرات الصوتية في صفحة النماذج.
- **عقل الوكيل:** Claude Sonnet 4.6 / Opus 4.8 / Opus 4.7، وGemini 3.1 Pro / 3 Flash بحسب صفحة Tab العامة.

هذه قائمة نماذج معلنة على موقع Tab وليست إثباتاً بأن كل نموذج متاح عبر API عام أو في كل بلد/حساب أو بنفس الحدود. لا نفترض أن Tab يستخدم هذه النماذج لكل ميزة أو أن قائمة المزودين ثابتة.

### المستندات والملفات
Tab يعلن قدرات وكيل لإنشاء المستندات والجداول والعروض والملفات، وتحرير المستندات الموجودة بتحريرات موضعية (find/replace، إعادة صياغة، إعادة هيكلة مع الحفاظ على بقية المحتوى)، والتصدير إلى PDF وPowerPoint وExcel في خطط/خصائص معينة. الصفحات العامة لا تكشف بصورة موثوقة نموذجاً أساسياً واحداً مسؤولاً عن كل عمليات المستندات؛ لذلك **لا ننسب المستندات إلى Claude أو Gemini أو غيرهما دون دليل**. يجب أن يكون NIKO قادراً على تركيب هذه المهام من نموذج لغوي + أدوات قراءة/تحرير ملفات + محركات تحويل/تصدير واختبارات صحة.

## 2. هدف التكافؤ في NIKO

تجربة موحدة؛ لا يضطر المستخدم لاختيار النموذج:
1. يصف ما يريد بلغته الطبيعية أو يرفع مرجعاً.
2. NIKO يفهم الهدف، ويقترح سؤالاً واحداً فقط إذا كانت معلومة أساسية ناقصة.
3. يختار تلقائياً أفضل مسار متاح وفق الجودة، نوع المدخلات، الخصوصية، السرعة، التكلفة والحدود.
4. يعرض معاينة/خطة قصيرة عندما تفيد.
5. ينشئ نسخة، يسمح بالتكرار والتعديلات دون فقد النسخ السابقة.
6. يتحقق من الملف الناتج فعلياً ثم يتيح المعاينة والتنزيل والمشاركة.
7. يحفظ المشروع ومصادره ونسخه في مساحة المستخدم الخاصة.

يجب توفير **Auto mode** افتراضياً، و**Manual/Advanced mode** اختيارياً لعرض النماذج المتاحة فعلياً فقط.

## 3. معمارية Model Router

عقود منفصلة لكل قدرة:
- `TextModelProvider`: محادثة، تخطيط، تلخيص، توليد نصوص.
- `VisionProvider`: فهم الصور والمستندات المصورة.
- `ImageGenerationProvider`: نص إلى صورة.
- `ImageEditProvider`: صورة إلى صورة، تعليمات تعديل، أقنعة/مناطق إن دعمها المزود.
- `VideoGenerationProvider`: نص/صورة/مراجع إلى فيديو.
- `VideoEditProvider`: تعديل/تحرير مقاطع إن توفر API مناسب.
- `SpeechToTextProvider`: تحويل الصوت إلى نص.
- `TextToSpeechProvider`: توليد صوت الرد/التعليق.
- `MusicProvider` و`SoundEffectProvider`.
- `DocumentToolchain`: قراءة، استخراج، تحرير، إنشاء، تحويل، فحص وتصدير الملفات.

كل adapter يعرّف: الاسم والإصدار، القدرات الدقيقة، أنواع المدخلات/المخرجات، القيود، مناطق التوفر، المصادقة، مهلة التنفيذ، حدود التزامن، تقدير التكلفة، سياسة الاحتفاظ/التدريب، شروط الترخيص، دعم العربية وRTL، وhealth status. لا يُعرض المزود في Manual mode إلا إذا كان configured وavailable.

### اختيار المزود
يحسب Router أفضل خيار من:
- ملاءمة المهمة وقدرات API الفعلية.
- جودة مرجعية مقاسة على مجموعة NIKO.
- دعم النصوص العربية/التركية والكتابة داخل الصور عند الحاجة.
- اتساق الشخصيات/المنتجات والمراجع والتحكم في المشاهد.
- دقة/مدة/نسبة أبعاد/صوت أصلي مدعوم فعلياً.
- زمن الاستجابة والتوفر.
- تكلفة متوقعة وحدود المستخدم والميزانية.
- خصوصية البيانات وموقع المعالجة وسياسة الاحتفاظ.
- شروط الاستخدام وحقوق المخرجات.

لا تختَر نموذجاً لمجرد شهرته أو ترتيب تسويقي. لا تُرسل بيانات حساسة إلى مزود إلا بعد الإفصاح والموافقة والإعداد الملائم.

## 4. استوديو الصور

### الوظائف
- Text-to-image مع وصف طبيعي ومقاسات 1:1 و4:5 و9:16 و16:9 حيث يدعم المزود.
- Image-to-image باستخدام صورة مرجعية يملك المستخدم حق استخدامها.
- تعديل موضعي/قناع/إزالة خلفية/استبدال خلفية/توسيع الإطار/تحسين الدقة إذا كان ذلك مدعوماً.
- المحافظة على هوية المنتج/الشخصية/الملابس عبر المراجع، مع إظهار حدود الاتساق بدلاً من ضمانه.
- نسخ متعددة، سجل نسخ، إعادة توليد، مقارنة قبل/بعد.
- حفظ prompt والإعدادات ومعرف المزود وإصدار النموذج مع كل أصل، مع عدم تخزين أسرار المزود.
- تنزيل الملف الأصلي المتاح مع بيانات أبعاده وصيغته.

### القبول
- اختبار توليد حقيقي واحد على الأقل لكل مزود مفعل.
- اختبار تحرير صورة مرفوعة وصلاحية الناتج.
- فحص نوع الملف وحجمه وأبعاده، وعدم الثقة في امتداد الملف وحده.
- اختبار فشل المزود وانتهاء المهلة وإعادة المحاولة دون مضاعفة التكلفة بلا قصد.
- اختبار ملكية الأصل والنسخ والتنزيل بين مستخدمين.

## 5. استوديو الفيديو

### الوظائف
- Text-to-video وImage-to-video وReference-guided generation حسب API المتاح.
- إعداد brief ثم storyboard/shot list قابل للتعديل قبل التوليد.
- تقسيم المشهد الطويل إلى لقطات؛ اختيار نموذج مناسب لكل لقطة عند الحاجة.
- تحكم في المدة ونسبة الأبعاد والدقة والإطارات/الصوت وفق حدود المزود.
- دعم start/end frame أو صور/فيديو/صوت مرجعي فقط عندما ينص API الفعلي على ذلك.
- تعليق صوتي وموسيقى ومؤثرات اختيارية مع حقوق استخدام واضحة.
- Timeline أساسي للقص والدمج والعناوين والترجمة، عبر محرك محلي/خادمي موثق.
- Jobs غير متزامنة: create/status/cancel/retry/download، مع progress حقيقي من المزود أو حالة واضحة إذا لم يتوفر.
- الاحتفاظ بكل إصدار وإمكانية الرجوع إليه.

### القبول
- توليد MP4 حقيقي قابل للتشغيل من مهمة مكتملة.
- فحص codec/container/duration/resolution/audio stream.
- اختبار الإلغاء والمهلة وانقطاع الشبكة وإعادة المحاولة وwebhook مكرر.
- لا تعرض نسبة تقدم مخترعة إذا كان المزود لا يقدم progress.
- تحقق من ملكية كل job ومرجع ومقطع وملف نهائي.

## 6. المستندات والإنتاجية

### أنواع العمل
- إنشاء وتحرير DOCX وPDF وXLSX وPPTX وCSV وTXT وMarkdown.
- استيراد ملفات موجودة، استخراج النص والجداول والصور، تلخيصها، والبحث داخلها.
- تحرير موضعي يحافظ على الأجزاء غير المطلوبة؛ لا تعِد بناء المستند كله عند طلب تعديل فقرة واحدة.
- قوالب CV ورسائل التقديم والتقارير والعروض والجداول.
- دعم العربية RTL، اتجاه الفقرات والجداول والخطوط والأرقام، مع معاينة فعلية.
- تتبع التغييرات والنسخ وإمكانية التراجع.
- منع اختلاق معلومات شخصية أو مهنية في CV أو أي مستند واقعي.

### Toolchain
استخدم مكتبات/محركات متخصصة لكل صيغة، والنموذج اللغوي للفهم والتحرير لا كبديل عن التحقق البنيوي:
- DOCX: إنشاء/تحرير وفحص فتح المستند.
- PDF: استخراج/إنشاء، تضمين خطوط مناسبة، وفحص الصفحات وRTL.
- XLSX: صيغ وخلايا وأنماط وجداول، مع فحص سلامة المصنف.
- PPTX: شرائح وتخطيط ونصوص وصور، مع فحص عدد الشرائح وعرضها.
- CSV/TXT/MD: ترميز UTF-8، اقتباس CSV، وعدم إفساد النص العربي.
- OCR: مسار اختياري للصور والصفحات الممسوحة مع بيان مستوى الثقة.

### القبول
- عينات اختبار لكل صيغة مدعومة، تُفتح بأداة تحقق أو parser مناسب.
- اختبار عربي RTL وإنجليزي مختلط وأرقام وجداول.
- اختبار تحرير موضعي يثبت أن المحتوى غير المستهدف بقي دون تغيير.
- اختبار ملف تالف/ضخم/امتداد مزيف/محتوى خبيث.
- اختبار عزل الملفات والمقتطفات والفهارس بين المستخدمين.

## 7. إدارة الملفات والمشاريع

- لكل مستخدم Workspace خاص ومشاريع وأصول ونسخ.
- سجل أصل موحد: owner، project، type، storage key داخلي، MIME متحقق، size، checksum، created_at، provider metadata، retention state.
- التخزين خاص افتراضياً؛ لا تستخدم public bucket.
- التنزيل عبر endpoint يتحقق من الملكية أو signed URL قصير العمر.
- فحص ملفات الرفع قبل التحليل؛ حدود حجم ومعدل؛ عزل parsers/workers.
- حذف/تصدير بيانات المستخدم وفق سياسة موثقة، بما يشمل النسخ والمهام والفهارس حيث ينطبق.
- لا تضع روابط التخزين الدائمة أو مفاتيح المزود في سجلات التطبيق.

## 8. سياسة التكلفة والتفعيل

- لا توجد مكالمات مدفوعة أو اشتراكات أو بنية تحتية billable دون موافقة صريحة من مالك المشروع.
- كل طلب خارجي يمر عبر Cost Guard: تقدير/حد أقصى إن توفر، رصيد/حصة المستخدم، حدود المشروع، حد التزامن، وkill switch.
- لا تبدأ توليد فيديو أو صور باهظة قبل تأكيد المستخدم عندما تتجاوز العملية حد التكلفة الذي يحدده المنتج.
- دعم مزود محلي/مجاني لا يعني جودة مكافئة؛ اعرض الفرق بصدق.
- مفاتيح المزود تحفظ في secret manager على الخادم، لا في Flutter ولا Git.

## 9. الخصوصية والأمان متعدد المستخدمين

- JWT/جلسة موثقة لكل endpoint خاص.
- owner ID مشتق حصراً من principal موثق.
- RLS/قيود DB + تحقق ملكية على مستوى service لكل أصل وjob.
- Workers تستلم job ID موقّع/موثوقاً وتعيد تحميل مالك المهمة من DB؛ لا تثق بـ owner ID في payload.
- منع IDOR في العرض والبحث والصفحات والتنزيل والتعديل والحذف.
- سجلات منقحة؛ لا تحفظ prompts أو الملفات أو التسجيلات الخام إلا لسبب واضح وموافقة وسياسة احتفاظ.
- rate/concurrency/spend limits على مستوى المستخدم والمزود وIP، مع backpressure.

## 10. واجهة المستخدم

- صفحة Create مركزية: Chat / Image / Video / Documents / Audio، مع بقاء الصوت هو نقطة الدخول الأساسية للمساعد.
- Auto mode هو الافتراضي؛ لا تزدحم الواجهة بقائمة نماذج للمستخدم العادي.
- Manual mode يعرض القدرات والقيود والتكلفة التقديرية والتوفر، لا أسماء غير مهيأة.
- عرض المراجع والنسخ وحالة المهمة وإجراءات الإيقاف/الإلغاء.
- معاينة الملف أو الوسائط قبل التنزيل/المشاركة.
- لا تُعرض أزرار أو ميزات غير متاحة كأنها تعمل.

## 11. مراحل التنفيذ

1. Provider contracts + registry + capability discovery + cost/policy guard.
2. Documents toolchain والاختبارات قبل توصيل مزودات مدفوعة.
3. Image provider adapter وImage Studio، مع موصل واحد اختباري محلي/مفعل بعد الموافقة.
4. Video job lifecycle وواجهة موصلات، ثم اختبار مزود بعد الموافقة.
5. Voice/STT/TTS/music adapters ومقاييس اللهجات.
6. Auto router + manual advanced selector + project/version history.
7. اختبارات أمن، حمل، جودة وتكلفة، ثم بوابة إطلاق iPhone.

## 12. تعريف الإنجاز

الميزة تكون **implemented** فقط إذا كان الكود موجوداً، و**configured** فقط إذا كانت بيانات الاعتماد/الإعدادات متوفرة، و**tested** فقط إذا اجتازت اختباراً فعلياً موثقاً. لا تُعد واجهة أو mock أو API stub أو وثيقة مواصفات ميزة مكتملة. لا يُعلن إطلاق عام قبل اجتياز الأمان، الخصوصية، اختبار الأجهزة، وسياسات مزودي النماذج.
