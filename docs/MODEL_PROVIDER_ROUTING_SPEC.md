# مواصفات توجيه مزودي الذكاء الاصطناعي والنماذج في NIKO

**الحالة:** مواصفات اختيار وتكامل واختبار. قائمة النماذج أدناه مرجع للمقارنة، وليست إعلاناً عن تكامل أو إتاحة أو سعر أو ترخيص داخل NIKO.
**مرجع المقارنة:** صفحة Tab الرسمية `workspace.tab.bot` وصفحة النماذج، كما تمت مراجعتهما بتاريخ 15 نوفمبر 2026. قد تتغير الأسماء والإصدارات والتوفر.

## 1. الهدف

يجب ألا يرتبط NIKO بنموذج واحد. يختار النظام أفضل محرك متاح لكل مهمة بناءً على جودة النتيجة، واللغة واللهجة، ونوع الوسائط، والسرعة، والتكلفة، والخصوصية، وحقوق الاستخدام، والتوفر الجغرافي. يستطيع صاحب المشروع تغيير المزود أو تعطيله دون تعديل تطبيق Flutter.

## 3. فئات المحركات في NIKO

يُبنى Provider Router على فئات منفصلة:

1. **Reasoning/Agent:** فهم النية، التخطيط، اختيار المهارة، التحقق من النتائج.
2. **Chat/Language:** المحادثة العامة، العربية واللهجات، الإنجليزية والتركية.
3. **Speech-to-Text:** تفريغ الصوت مع timestamps واكتشاف تبديل اللغة.
4. **Text-to-Speech:** صوت رجالي مناسب عند توفره، مع نطق طبيعي للغات المطلوبة.
5. **Vision/Document Understanding:** فهم الصور وPDF والمستندات والجداول.
6. **Image Generation/Edit:** إنشاء الصور، تعديلها، الأقنعة، الصور المرجعية.
7. **Video Generation/Edit:** نص/صورة/فيديو مرجعي إلى فيديو، تحرير اللقطات، المشاهد.
8. **Music/Sound Effects:** صوت وموسيقى مرخصة ومؤثرات.
9. **Embeddings/Reranking:** استرجاع ذاكرة المستخدم وملفاته ضمن نطاق حسابه فقط.

## 4. عقد Provider Adapter

كل Adapter يلتزم بعقد موحد يشمل:

- `provider_id`, `model_id`, `model_version`.
- `capabilities`: أنواع المهام المدعومة.
- `input_schema` و`output_schema` مع التحقق من الملفات والحدود.
- اللغات واللهجات المدعومة فعلياً ونتائج القياس.
- مناطق التوفر، متطلبات الحساب، حدود الطلبات، وحجم الملفات.
- السعر/وحدة الاستهلاك، الحد الأقصى المتوقع، ورسوم التخزين/التنزيل إن وجدت.
- سياسة الاحتفاظ بالمدخلات والمخرجات ومكان المعالجة واستخدام البيانات في التدريب.
- حقوق الاستخدام التجاري وقيود المحتوى والترخيص.
- دعم async jobs، webhooks/polling، الإلغاء، واسترجاع الحالة.
- مهلات، retry policy، idempotency، rate limits.
- health status: `available`, `degraded`, `disabled`, `unconfigured`, `unavailable`.
- مؤشرات جودة وزمن وتكلفة، دون تسجيل محتوى المستخدم الخاص.

لا يُسجل أي Adapter على أنه `available` إلا إذا كانت بيانات اعتماده موجودة في secret manager، ونجح اختبار صحة غير مكلف، واجتاز اختبار عقده. يجب أن يكون تعطيله فورياً من إعدادات الخادم.

## 5. منطق اختيار النموذج

يختار NIKO المحرك وفق الترتيب التالي:

1. نوع المهمة والمخرج المطلوب.
2. سلامة المدخلات والحقوق والصلاحيات.
3. اللغة/اللهجة وجودة النموذج المقاسة لهذه المهمة.
4. توفر المزود والمنطقة والمهلة المتوقعة.
5. التكلفة المتوقعة وحدود المستخدم والميزانية.
6. سياسة الخصوصية والاحتفاظ بالبيانات.
7. التفضيل الصريح للمستخدم إن كان متوافقاً مع كل ما سبق.

لا تختَر نموذجاً لمجرد أنه أحدث أو أعلى ترتيباً تسويقياً. استخدم مصفوفة benchmark داخلية على مهام NIKO الواقعية. يمكن أن يختار Agent mode تلقائياً أو Manual mode اختياراً صريحاً عند رغبة المستخدم، لكن لا يُطلب منه اختيار مزود في كل طلب.

## 6. قواعد التكلفة والميزانية

- الهدف التشغيلي المبدئي صفر ريال عماني؛ لا توجد موافقة ضمنية على الدفع.
- المزودات المدفوعة تبقى `disabled` حتى موافقة صريحة على المزود والحد المالي/الائتماني.
- لا تبدأ تجربة مجانية تتطلب بطاقة أو تتحول تلقائياً إلى اشتراك دون موافقة.
- لا تنفذ توليد صورة/فيديو مدفوعاً لمجرد اختبار CI.
- قبل أي مهمة مدفوعة، اعرض تقديراً أو سقفاً موثوقاً، وعدد المخرجات والجودة والمدة.
- ضع per-user spend cap وglobal spend cap وconcurrency cap.
- عند عدم معرفة التكلفة مسبقاً، لا تنفذ الطلب المدفوع؛ اعرض أن التكلفة غير معروفة واطلب قراراً.
- دعم محلي/مفتوح المصدر خيار بديل فقط إذا كانت الجودة والأداء والخصوصية مقبولة على العتاد المستهدف.

## 7. الخصوصية والأمن

- جميع مفاتيح المزودين server-side فقط؛ لا توضع في Flutter أو Git أو سجلات CI.
- لا تمرر بيانات المستخدم إلى مزود لا يحقق سياسة الخصوصية المعلنة.
- إزالة البيانات غير الضرورية من الطلبات، وتحديد retention، وعدم استخدام البيانات في تدريب النموذج دون موافقة منفصلة.
- ربط كل job وasset بالمستخدم الموثق والتحقق من الملكية عند القراءة والتنزيل والحذف.
- عدم وضع prompt أو transcript أو محتوى مستند في logs؛ استخدم request IDs وmetadata منقحة.
- فصل أسرار المزودين حسب البيئة، وتدويرها، وتعطيلها عند التسريب.
- رفض روابط الملفات الخارجية غير الموثوقة أو التحقق منها لمنع SSRF.

## 8. الاختبارات والمقارنة

لكل فئة محرك:
- Contract tests للمدخلات والمخرجات والأخطاء.
- اختبارات جودة متعددة اللغات، بما فيها العربية واللهجات والمزج.
- قياس latency وtimeout وthroughput.
- اختبارات file size/type وmalformed output.
- اختبار cancellation/retry/idempotency للمهام الطويلة.
- اختبار فشل المزود والانتقال إلى fallback آمن.
- قياس التكلفة الحقيقية في بيئة اختبار مصرح بها فقط؛ CI يستخدم mocks أو sandbox مجاني لا يسبب فواتير.
- مقارنة مخرجات بشرية التقييم مع حفظ الإصدار والبيانات الاختبارية غير الشخصية.
- اختبار ملكية jobs والملفات بين مستخدمين مختلفين.

## 9. بوابات إضافة مزود جديد

لا تتم إضافة مزود إلى الإنتاج قبل إرفاق:
1. رابط API الرسمي ووثائق المطور.
2. إثبات أن النموذج/الإصدار متاح عبر API، لا داخل تطبيق الطرف الثالث فقط.
3. شروط الاستخدام والترخيص التجاري.
4. المناطق واللغات والملفات المدعومة.
5. الأسعار وحدود الاستخدام وسياسة الإلغاء.
6. سياسة البيانات والاحتفاظ والتدريب.
7. اختبارات adapter والجودة والأمن.
8. موافقة صاحب المشروع إذا كانت هناك تكلفة أو اشتراك أو نقل بيانات حساسة.

## 10. تعريف الإنجاز

تعتبر بنية التوجيه مكتملة عندما يستطيع NIKO اختيار محرك متاح وفق المهمة، وتسجيل سبب الاختيار دون تسريب المحتوى، وتطبيق سقف التكلفة، والتعامل مع الفشل، وتقديم مخرج حقيقي تم التحقق منه. وجود قائمة نماذج أو أسماء مزودين في الإعدادات لا يحقق هذا التعريف.
