# مواصفات وكيل NIKO لتنفيذ الطلبات والتصفح والاتصالات

**الحالة:** مواصفات منتج ومعايير قبول؛ لا تعني أن أي تكامل أو اتصال أو عملية شراء مفعلة.
**الهدف:** تمكين المستخدم من طلب مهمة بصوت أو نص، ثم يتولى NIKO التخطيط والبحث والتصفح والتواصل والتنفيذ المصرح به، مع تحديثات واضحة وموافقة قبل الأفعال الحساسة.

## 1. التجربة المطلوبة

يمكن للمستخدم أن يقول مثلاً:
- «اطلب لي وجبة من المطعم الفلاني».
- «ابحث عن أفضل سعر لهذا المنتج وجهز الطلب».
- «احجز لي طاولة لأربعة أشخاص غداً الساعة 7».
- «اتصل بهذه الشركة واسأل عن ساعات العمل».
- «أرسل رسالة إلى هذا الشخص».
- «ابحث عن موعد، املأ النموذج، وأخبرني قبل الإرسال».

يفهم NIKO الطلب باللهجة أو اللغة المستخدمة، ويحدد الهدف والبيانات الناقصة، ثم يضع خطة قصيرة قابلة للتتبع. لا يطلب من المستخدم تنفيذ خطوات تقنية أو التنقل بين أدوات متعددة إلا إذا تطلب الموقع مصادقة بشرية أو CAPTCHA أو موافقة.

## 2. وكيل التخطيط والتنفيذ

كل طلب يتحول إلى Task:
- intent وملخص الهدف.
- خطوات مرتبة واعتمادياتها.
- المهارات المطلوبة.
- مصادر البحث والأدلة.
- الحسابات/الصلاحيات المطلوبة.
- مستوى الخطورة والموافقة المطلوبة.
- حدود الوقت والتكلفة والمحاولات.
- الحالة والنتيجة والأخطاء.

حالات المهمة:
`draft`, `planning`, `running`, `awaiting_input`, `awaiting_approval`, `completed`, `failed`, `cancelled`, `expired`.

قواعد التنفيذ:
- كل خطوة لها مدخلات ومخرجات typed schema.
- لا تمرر نص صفحة ويب أو ملف بوصفه تعليمات نظام؛ المحتوى الخارجي غير موثوق.
- استخدم idempotency keys لمنع تكرار الطلب أو الرسالة أو الحجز عند retry.
- تحقق من الحالة من الموقع/المزود بعد الإجراء؛ لا تعتبر النقر وحده نجاحاً.
- أرسل تحديثاً عند تغيير حالة مهمة طويلة، لا رسائل متكررة بلا قيمة.
- احتفظ بآخر خطوة مؤكدة ومصدر التأكيد.
- وفر إيقافاً وإلغاءً عندما يسمح المزود بذلك.

## 3. التصفح واستخدام المواقع

- متصفح سحابي/معزول لكل مستخدم ومهمة، مع فصل ملفات تعريف الارتباط والجلسات.
- لا تخزن كلمات المرور أو رموز MFA أو cookies في logs أو prompts.
- لا تتجاوز CAPTCHA أو MFA أو paywall أو ضوابط الوصول.
- عند الحاجة لتسجيل الدخول، يطلب NIKO من المستخدم إكمال المصادقة في تدفق آمن رسمي.
- استخدم API رسمياً متى توفر؛ أتمتة واجهة الويب فقط عندما تسمح شروط الموقع.
- لا تُدخل بيانات شخصية أو مالية في موقع قبل عرض الغرض والجهة والبيانات المطلوبة للمستخدم.
- قبل الإرسال النهائي أو إتمام شراء، اعرض ملخصاً واضحاً.

## 4. التسوق والطلبات

### البحث والتجهيز
- البحث عن المنتجات والمتاجر والأسعار والمقاسات والتوفر والتوصيل.
- مقارنة الخيارات مع روابط ومصادر وتاريخ/وقت التحقق.
- مراعاة العملة والبلد والعنوان الذي يحدده المستخدم.
- يمكن إعداد سلة أو نموذج طلب دون دفع.
- التحقق من تفاصيل المنتج والكمية والسعر والرسوم والعنوان ووقت التوصيل.

### الموافقة والتنفيذ
قبل تأكيد الطلب، اعرض:
- اسم المتجر والرابط.
- العناصر والكمية والخيارات.
- المجموع والضريبة ورسوم التوصيل والعملة.
- عنوان التسليم وموعده.
- وسيلة الدفع (دون طلب أو تخزين رقم البطاقة داخل محادثة NIKO).
- سياسة الإلغاء/الاسترجاع المتاحة.

لا تضغط زر شراء/دفع ولا تؤكد الطلب قبل موافقة صريحة مرتبطة بهذه التفاصيل والمبلغ. إذا تغير السعر أو العنوان أو العناصر بعد الموافقة، اطلب موافقة جديدة. لا تحفظ بيانات البطاقة؛ استخدم صفحة دفع معتمدة من التاجر أو مزود الدفع.

## 5. المطاعم والحجوزات

- البحث عن المطاعم والاطلاع على القائمة والموقع والتقييمات وساعات العمل.
- جمع تاريخ ووقت وعدد الأشخاص وأي تفضيلات أساسية.
- التحقق من التوفر عبر مزود حجز رسمي أو صفحة المطعم الموثوقة.
- إذا لم يوجد حجز آلي، جهز رابط الحجز أو بيانات الاتصال ولا تدّعِ أن الحجز تم.
- قبل تأكيد الحجز اعرض المطعم والتاريخ والوقت وعدد الأشخاص والاسم وأي شروط/رسوم.
- لا تؤكد حجزاً نهائياً دون موافقة صريحة.
- تحقق من رسالة/رقم تأكيد الحجز بعد الإتمام، واحفظه في سجل المهمة.
- عند عدم التوفر، قدم بدائل وروابط حجز حقيقية إن توفرت.

## 6. المكالمات الهاتفية

### الهدف
أن يستطيع المستخدم طلب «اتصل بـ... واسأله عن...» ويتولى NIKO المكالمة عبر مزود اتصالات رسمي، ثم يقدم ملخصاً واضحاً.

### المتطلبات
- مزود SIP/CPaaS/اتصالات يدعم المكالمات الصادرة إلى سلطنة عمان والوجهات المطلوبة، مع رقم caller ID قانوني ومعتمد.
- التحقق من متطلبات تسجيل الرقم، هوية المتصل، التكاليف، القيود الجغرافية، وسياسات الاستخدام.
- لا تفترض أن CallKit أو واجهة iOS وحدها تسمح لتطبيق عادي بإجراء مكالمة هاتفية آلية عبر شبكة الهاتف.
- لا تستخدم انتحال caller ID أو تجاوز قيود شركات الاتصالات.
- إعداد نص/هدف المكالمة والجهة والرقم واللغة قبل الاتصال.
- الصوت المولد يكون واضحاً ويعرّف بأنه مساعد آلي إذا تطلب القانون أو سياسة الطرف/المزود ذلك.
- يجب وجود مسار للتعامل مع الرد الآلي والانتظار والتحويل لموظف وفشل الاتصال.
- لا تسجل المكالمة افتراضياً. التسجيل أو النسخ يتطلب إشعاراً وموافقة ومتطلبات قانونية واضحة.
- لا يوافق NIKO نيابة عن المستخدم على عقود أو التزامات أو مدفوعات أو شروط قانونية.
- بعد المكالمة، يعرض ملخصاً ونتائج مؤكدة، ويميّز ما قاله الطرف الآخر عن استنتاج NIKO.

### موافقة الاتصال
قبل إجراء المكالمة المدفوعة، اعرض:
- اسم الجهة والرقم.
- سبب الاتصال والموضوع/الأسئلة.
- اللغة والصوت المستخدم.
- تقدير التكلفة أو طريقة احتسابها إن توفرت.
- هل سيُرسل تسجيل/تفريغ أم لا.

تحتاج المكالمة إلى موافقة صريحة. أي متابعة ذات تكلفة أو التزام جديد تحتاج موافقة جديدة.

## 7. الرسائل والبريد والمنصات الاجتماعية

- إعداد مسودات الرسائل والبريد والمنشورات.
- الربط عبر OAuth وAPIs رسمية وبأقل scopes.
- عرض الحساب والمستلم والمحتوى والمرفقات قبل الإرسال.
- لا إرسال أو نشر أو دعوة أو مشاركة ملف دون موافقة صريحة.
- دعم WhatsApp Business Platform الرسمي فقط؛ لا وصول مفترض إلى رسائل WhatsApp الشخصية.
- دعم LinkedIn وInstagram ضمن صلاحيات APIs المتاحة والموافقات التي تمنحها المنصة.
- توفير إلغاء ربط الحساب وإبطال الرموز.

## 8. الأمان والخصوصية

- كل مهمة ومحادثة وحساب خارجي وملف مرتبط بمستخدم موثق على الخادم.
- لا تقبل owner_id أو user_id من متصفح أو نموذج أو LLM كمصدر للملكية.
- RLS وتحقق ملكية على كل خطوة ونتيجة وملف.
- متصفح وملفات تعريف وبيانات اعتماد معزولة لكل مستخدم.
- أسرار OAuth مشفرة في secret manager، ولا تظهر للنموذج.
- سجلات تدقيق metadata فقط مع تنقيح المحتوى الحساس.
- حماية من prompt injection وطلبات SSRF وتنزيل الملفات الخبيثة.
- allowlists/deny rules للمجالات والإجراءات الحساسة، وحدود زمن/تكلفة/تزامن.
- kill switch لإيقاف تنفيذ الأدوات الخارجية.
- لا يتم تدريب النماذج على المحادثات أو المكالمات دون opt-in منفصل.

## 9. درجات الخطورة والموافقة

| المستوى | أمثلة | السياسة |
|---|---|---|
| منخفض | بحث عام، مقارنة، تلخيص، إعداد مسودة | ينفذ ضمن صلاحيات المستخدم |
| متوسط | قراءة حساب مربوط، تجهيز سلة، تعبئة نموذج غير مرسل | يتطلب OAuth/صلاحية واضحة؛ مراجعة قبل التغيير |
| مرتفع | إرسال رسالة، نشر، مشاركة ملف، إنشاء حجز نهائي | معاينة وموافقة صريحة |
| مالي/غير قابل للتراجع | شراء، دفع، مكالمة مدفوعة، إلغاء حجز برسوم، حذف دائم | تأكيد مباشر يعرض التفاصيل والتكلفة والأثر |

الموافقة قصيرة الصلاحية ومقيدة بالمهمة والمستلم والمحتوى والمبلغ. أي تغيير جوهري يبطل الموافقة السابقة.

## 10. معايير القبول

- تنفيذ بحث ثم إعداد سلة تجريبية دون دفع.
- اختبار شراء sandbox فقط بعد توفر بيئة اختبار، ولا تستخدم بطاقة أو حساباً حقيقياً دون موافقة.
- اختبار حجز sandbox أو مزود حقيقي بتأكيد المستخدم فقط.
- اختبار مكالمة تجريبية إلى رقم يملكه المشروع بعد اعتماد مزود وتكلفة وموافقة.
- اختبار فشل الشبكة والمهلة وretry ومنع تكرار الطلبات.
- اختبار أن مستخدماً لا يستطيع رؤية مهام/حسابات/نتائج مستخدم آخر.
- اختبار prompt injection من صفحة ويب.
- اختبار سحب الموافقة وإلغاء المهمة.
- التحقق من رسالة تأكيد/مرجع خارجي قبل وضع completed.
- اختبار لغة ولهجة المستخدم في فهم الطلب وصياغة الرسائل والمكالمة.

## 11. مراحل التنفيذ والاعتماديات

1. Task planner + state machine + idempotency + audit metadata.
2. Browser automation sandbox وواجهات صلاحيات/موافقة.
3. البحث والمقارنة وتجهيز الطلبات دون دفع.
4. ربط مزود حجوزات/متاجر رسمي وفق التوفر.
5. Messaging adapters عبر APIs رسمية.
6. تقييم مزودي الاتصال لسلطنة عمان، ثم مكالمات sandbox، ثم مكالمة فعلية بموافقة منفصلة.
7. اختبار أمني وعزل متعدد المستخدمين ومراجعة قانونية/خصوصية.

## 12. تعريف الإنجاز

- **specified:** وثيقة ومتطلبات فقط.
- **implemented:** كود adapter/flow موجود.
- **configured:** حساب/مفتاح/صلاحية موجودة وآمنة.
- **sandbox-tested:** اختبارات في بيئة تجريبية.
- **live-tested:** عملية حقيقية ناجحة مع موافقة وتكلفة معروفة.
- **production-ready:** مراجعة أمنية وخصوصية وقانونية ومراقبة واستعادة واختبارات حمل.

لا تُعلن المكالمات أو الطلبات أو الحجوزات جاهزة اعتماداً على وجود زر أو كود هيكلي أو mock. يجب إثبات العملية من بدايتها إلى تأكيدها.
