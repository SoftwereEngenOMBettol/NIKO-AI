# نطاق النسخة الأولى المقترح (MVP Scope)

- الإصدار: 0.1
- الحالة: مقترح للموافقة، وليس قراراً نهائياً.
- الهدف: بناء نسخة صغيرة حقيقية تثبت أساس NIKO قبل إضافة التكاملات المعقدة.

## 1. هدف النسخة الأولى
إثبات أن NIKO يستطيع استقبال طلب المستخدم، فهم لغته، الرد بصورة طبيعية، تنفيذ مجموعة مهام آمنة، والاحتفاظ بسياق اختياري دون تعريض بياناته للخطر.

## 2. ما يدخل في MVP
### أ. المحادثة واللغات
- واجهة محادثة نصية.
- العربية والإنجليزية والتركية.
- اكتشاف لغة المستخدم تلقائياً.
- محاولة التكيّف مع اللهجة العربية المستخدمة.
- دعم الجمل المختلطة لغوياً.
- إمكانية تغيير لغة الرد بأمر مباشر.

### ب. الصوت
- تسجيل صوت المستخدم من داخل التطبيق.
- تحويل الكلام إلى نص.
- رد صوتي عند توفر محرك مجاني مناسب.
- صوت رجولي كهدف تصميمي، على أن يُختبر دعم اللغات الثلاث.
- عرض النص بجانب الصوت لتصحيح أخطاء التعرف.

### ج. عقل NIKO
- تحليل الطلب والتمييز بين السؤال والمهمة.
- تقسيم الطلبات البسيطة إلى خطوات.
- إظهار حالة التنفيذ.
- إبلاغ المستخدم بوضوح عند الفشل أو نقص الصلاحيات.
- طبقة قابلة لتبديل مزود النموذج، مع تفضيل المحلي والمفتوح المصدر.

### د. المهارات الأولى
- إنشاء قائمة مهام محلية.
- إنشاء تذكيرات محلية وإشعارات من النظام.
- حفظ ملاحظات يختارها المستخدم.
- تلخيص النصوص التي يرسلها المستخدم.
- إعداد مسودات رسائل ومنشورات دون إرسالها تلقائياً.

### هـ. الذاكرة والخصوصية
- ذاكرة محلية اختيارية.
- عرض المعلومات المحفوظة.
- تعديلها وحذفها أو تعطيل الذاكرة.
- لا تُحفظ المحادثات الحساسة تلقائياً دون إعداد واضح.

### و. الأمان
- طلب الموافقة قبل أي إرسال أو نشر أو شراء أو حجز أو اتصال أو حذف.
- عرض الصلاحيات المطلوبة وسببها.
- عدم وضع مفاتيح API أو كلمات مرور في التطبيق أو GitHub.
- زر لإيقاف المهام وإلغاء التكاملات المتاحة.

## 3. ما يؤجل إلى ما بعد MVP
- كلمة تنبيه دائمة «نيكو» أثناء قفل iPhone أو استخدام تطبيق آخر.
- قراءة شاملة لرسائل WhatsApp أو تطبيقات الطرف الثالث.
- إرسال الرسائل آلياً.
- تكامل WhatsApp Business.
- النشر التلقائي على Instagram وLinkedIn.
- المكالمات الآلية أو رقم هاتف مستقل.
- الشراء والحجز الآلي.
- توليد الفيديو المتقدم.
- تشغيل نماذج ضخمة محلياً على كل الهواتف.
- مزامنة سحابية ومهام خلفية دائمة قبل إثبات استضافة مجانية موثوقة.

هذه الميزات لا تُلغى من رؤية المنتج؛ بل تحتاج دراسة مستقلة للقيود والتكلفة والأذونات.

## 4. معايير نجاح MVP
1. يستطيع المستخدم إجراء محادثة نصية دون تعطل.
2. ينجح في فهم أو تحديد لغة المحادثة بين العربية والإنجليزية والتركية في مجموعة اختبارات معلومة.
3. تُختبر اللهجات والجمل المختلطة وتُسجل النتائج دون ادعاء دقة كاملة.
4. يستطيع المستخدم إنشاء مهمة وتذكير محلي وتلقي إشعار النظام.
5. يستطيع المستخدم مراجعة ذاكرته وتعطيلها وحذف بياناتها.
6. لا ينفذ التطبيق إجراءً خارجياً حساساً دون موافقة صريحة.
7. لا يحتوي المستودع على أسرار أو مفاتيح.
8. توثق تكلفة كل مكوّن ومتطلبات تشغيله.

## 5. قرار تقني مطلوب قبل البرمجة
لا نثبت Flutter أو نموذجاً بعينه حتى نجري تجربة قصيرة ونقارن:
- سهولة التطوير من بيئة المستخدم المتاحة.
- دعم iOS وAndroid.
- جودة العربية واللهجات والإنجليزية والتركية.
- الأداء على الأجهزة المتوسطة.
- إمكانية التشغيل دون إنترنت.
- الترخيص والتكلفة وحدود الاستخدام.
- إمكانات الصوت والإشعارات في الخلفية.

## 6. بوابة الموافقة
قبل الانتقال إلى كتابة كود التطبيق، يجب اعتماد:
- نطاق MVP أعلاه أو تعديلاته.
- قرار التطبيق أولاً ثم التكاملات، أو تغيير الترتيب.
- حدود البيانات والذاكرة.
- خيارات التشغيل المجانية المقبولة.
